7``embedding_jobs`` rows transition to ``processing`` inside the drainer, but
8nothing recorded *which* worker claimed a job or *when*. A worker that died
9mid-upsert left its rows stuck in ``processing`` forever: the claim query only
10selects ``pending`` or retry-due ``failed`` rows, so no live worker could ever
11pick them up again.
12

15``processing`` when this migration runs predate the columns, so their
16``locked_by`` is backfilled as ``unknown``; their ``locked_at`` stays NULL and
17the reclaim treats a NULL lock timestamp as stale.
