Executable standard-library miniature RAG preparation: lexical retrieval plus a model-request packet. No generation provider is called.

What this demonstrates: Ask questions about a company's changing rules.

Connect it to the case: A shop assistant answers questions using approved return rules. The rule changes without retraining the language model.

import re

DOCUMENTS = [
    {"id": "general:r1", "text": "Standard items may be refunded within 30 days."},
    {"id": "sale:r3", "text": "Sale items can be exchanged within 14 days. Refunds are not offered for sale items."},
    {"id": "shipping:r2", "text": "Delivery takes 3 to 5 days."},
]

def words(text):
    return set(re.findall(r"[a-z0-9]+", text.lower()))

def retrieve(question):
    query = words(question)
    ranked = sorted(DOCUMENTS,
        key=lambda doc: len(query & words(doc["text"])), reverse=True)
    return [doc for doc in ranked[:1] if query & words(doc["text"])]

def assemble_request(question):
    evidence = retrieve(question)
    if not evidence:
        return {"status": "insufficient_evidence", "question": question}
    return {
        "status": "ready",
        "instructions": "Answer only from the evidence. Preserve exceptions. Cite its ID.",
        "question": question,
        "evidence": evidence,
    }

packet = assemble_request("Can I return a sale item?")
assert packet["evidence"][0]["id"] == "sale:r3"
assert "14 days" in packet["evidence"][0]["text"]
assert assemble_request("ZXQ123")["status"] == "insufficient_evidence"
# Inspect packet: these are the facts an approved generator would receive.
# This tiny lexical baseline has no semantic search, production auth, or live LLM.
How to read and test this code
  1. The documents are synthetic approved articles, each with a stable source ID.
  2. retrieve selects matching text; assemble_request puts that text beside the question and instructions.
  3. No model is called. Inspect the request a generator would receive, and compare an empty search.

  • packet['evidence'][0]['id'] == 'sale:r3'
  • '14 days' in packet['evidence'][0]['text']
  • assemble_request('ZXQ123')['status'] == 'insufficient_evidence'

The boundary to investigate: An old or irrelevant paragraph can still produce a wrong answer.

Standard library: numerically stable softmax for a toy attention row.

What this demonstrates: Understand what the model can and cannot do.

import math
def softmax(scores):
    maximum = max(scores)
    weights = [math.exp(score - maximum) for score in scores]
    total = sum(weights)
    return [weight / total for weight in weights]
assert abs(sum(softmax([1000, 1001])) - 1.0) < 1e-9
# Full attention also uses scaled query-key products, masks, and value vectors.
How to read and test this code
  1. Subtracting the largest score avoids exponentiating unnecessarily large numbers.
  2. softmax returns weights that sum to one; it does not verify a factual answer.
  3. The assertion checks numerical behavior, not the quality of a trained model.

Standard library: a toy word-window baseline, not a tokenizer.

What this demonstrates: Choose the unit of information that search can find.

def chunks(words, size=8, overlap=2):
    if not 0 <= overlap < size:
        raise ValueError("require 0 <= overlap < size")
    step = size - overlap
    for start in range(0, len(words), step):
        yield words[start:start + size]
        if start + size >= len(words): break
assert list(chunks(list(range(10)))) == [list(range(8)), list(range(6, 10))]
How to read and test this code
  1. step equals window size minus overlap, so neighboring windows repeat some words.
  2. The loop stops once the last window already covers the remaining input.
  3. This is a word-window baseline, not model-token-aware or section-aware chunking.

Standard library: reciprocal rank fusion uses rank rather than raw score.

What this demonstrates: Find the passages that can actually answer the question.

from collections import defaultdict
def rrf(rankings, k=60):
    scores = defaultdict(float)
    for ranking in rankings:
        for rank, item in enumerate(dict.fromkeys(ranking), 1):
            scores[item] += 1 / (k + rank)
    return sorted(scores, key=lambda item: (-scores[item], item))
assert rrf([["a", "b"], ["b", "c"]])[0] == "b"
How to read and test this code
  1. rrf accumulates a contribution from each item's position in each ranking.
  2. dict.fromkeys avoids giving repeated entries multiple votes within one list.
  3. The passage b wins by appearing in both lists; the result is a ranking, not calibrated confidence.

import codecs

def parse_sse(chunks):
    decoder = codecs.getincrementaldecoder("utf-8-sig")()
    line, data, kind, last_id, skip_lf, events = "", [], "", "", False, []
    def consume_line(value):
        nonlocal data, kind, last_id
        if value == "":
            if data:
                events.append({"event": kind or "message", "id": last_id,
                               "data": "\n".join(data)})
            data, kind = [], ""
            return
        if value.startswith(":"): return
        field, sep, text = value.partition(":")
        if text.startswith(" "): text = text[1:]
        if field == "data":
            data.append(text)
            if sum(map(len, data)) > 1_000_000: raise ValueError("event too large")
        elif field == "event": kind = text
        elif field == "id" and "\x00" not in text: last_id = text
        # retry and unknown fields are intentionally not acted on by this decoder.
    for chunk in chunks:
        for char in decoder.decode(chunk):
            if skip_lf:
                skip_lf = False
                if char == "\n": continue
            if char in "\r\n":
                consume_line(line)
                line = ""
                skip_lf = char == "\r"
            else:
                line += char
                if len(line) > 65536: raise ValueError("line too large")
    decoder.decode(b"", final=True)  # Reject truncated UTF-8; do not dispatch partial events.
    return events

  1. The incremental decoder handles characters split across byte chunks.
  2. The parser accumulates lines and dispatches data only at an event boundary.
  3. The final loop tries every split of one Unicode fixture; retry policy and JSON validation remain separate.

def selective_report(samples, threshold):
    chosen = [s for s in samples if s["score"] >= threshold]
    return {"coverage": len(chosen) / len(samples) if samples else 0,
            "accuracy": sum(s["correct"] for s in chosen) / len(chosen) if chosen else None}

How to read and test this code
