QUESTION 021CONCEPT + REFERENCE CASE#

21. Why distinguish discovery, fetching, extraction, and ingestion?

Read / reveal answer

Discovery enumerates source items. Fetching obtains bytes. Extraction converts those bytes into usable text and provenance. Ingestion chunks, embeds, and indexes the result. Keeping these boundaries separate lets the same extraction or indexing logic serve several source systems.

Mechanism & explanation

Connector records carry discovery and load status, while a source-document record carries content and source metadata into the pipeline. A PDF extraction failure is therefore different from an empty bucket or an embedding provider outage.

Risks & safeguards

Flattening every failure into an empty list can cause a later reconciliation to delete healthy knowledge. The connector contract represents errors and whether a result is authoritative; the pipeline refuses non-authoritative a typed scan result mutation.

Trade-offs

Rich status handling takes more code than returning strings. It supports safe retries, deletion decisions, and actionable diagnostics.

Apply it

Trace a PDF in an object bucket through all four stages. Specify the returned status when each stage fails and which stages can be retried independently.

QUESTION 022CONCEPT + REFERENCE CASE#

22. What makes a source scan authoritative?

Read / reveal answer

An authoritative scan represents the complete intended snapshot under its configured scope and traversal rules. A successful first page is not a complete snapshot. Authority also depends on whether errors, limits, or missing pages could have hidden existing documents.

Mechanism & explanation

A typed scan result distinguishes completeness and status; sync uses that authority to infer removals. The ordinary ingestion pipeline skips a non-authoritative a typed scan result rather than replacing its current indexed content with a partial view.

Risks & safeguards

Treating a timeout or permission error as authoritative emptiness can erase knowledge. Conversely, never trusting a complete empty scan leaves deleted content searchable. Both require explicit semantics.

Trade-offs

Conservative authority rules may delay deletion after a source outage. That delay is preferable to interpreting an incomplete traversal as proof of absence, but access revocation needs a separate immediate control.

Apply it

Simulate a three-page source where page two fails. Explain why the successfully fetched documents do not prove that all missing documents were deleted.

QUESTION 023CONCEPT + REFERENCE CASE#

23. How should pagination and checkpoints work for incremental ingestion?

Read / reveal answer

A cursor identifies where enumeration should continue; a checkpoint records safely processed progress. They are not interchangeable. Saving a cursor before the corresponding data is activated can skip work after a crash, while saving too late can repeat work.

Mechanism & explanation

Connectors expose page and full-load methods, and sync checkpoints are guarded by the example fencing token. Idempotency and complete-snapshot reconciliation make repeated pages safer than silently losing them.

Risks & safeguards

Sources may mutate between pages, causing duplicates or omissions even if every request succeeds. Stable ordering, source-side snapshot tokens where available, deduplication, and periodic full reconciliation are integration concerns.

Trade-offs

Full scans simplify reconciliation but cost more source I/O. Incremental feeds are faster but require careful resume and deletion semantics.

Apply it

Draw crashes immediately before activation, after activation, and after checkpoint saving. State which records will repeat and why no record should be skipped.

QUESTION 024CONCEPT + REFERENCE CASE#

24. How does the directory connector reduce filesystem risks?

Read / reveal answer

Directory ingestion must constrain traversal to an intended root, apply inclusion knowledge rules, bound resource use, and avoid unsafe path or symlink behavior. The connector implements explicit open, target, and read helpers rather than blindly opening every discovered string.

Mechanism & explanation

The directory adapter also records intentional skips separately from scan errors. That distinction preserves the meaning of completeness: a deliberately excluded file is not the same as an inaccessible file that should have been included.

Risks & safeguards

A local filesystem is not automatically trusted. Permission changes and concurrent file replacement can occur during scanning, and host deployment permissions still determine what the process can access.

Trade-offs

Strict traversal and file knowledge rules can exclude legitimate sources and need configuration. Broad scanning is easier to start and harder to secure or make reproducible.

Apply it

Read the directory connector's _open and _target helpers. Build a small temporary corpus containing ignored files, nested directories, and a symlink, and predict the reported skips.

QUESTION 025CONCEPT + REFERENCE CASE#

25. Why does an HTTP connector need SSRF protection?

Read / reveal answer

Server-Side Request Forgery occurs when a server fetches a destination chosen through untrusted input and reaches internal services or metadata endpoints. A document URL can be an attack input just as an API parameter can.

Mechanism & explanation

The HTTP connector validates destinations, pins requests to an approved public IP, disables automatic redirects, and checks redirects explicitly. It rejects attempts to turn off its network protections. Website crawling requires explicit allowed domains.

Risks & safeguards

Domain checking alone cannot stop DNS rebinding or redirect-based bypasses. Egress policy, deployment DNS behavior, and the actual client transport also matter. Treat source fetching as a separate trust boundary.

Trade-offs

Public-only fetching limits access to legitimate private knowledge services. Supporting private services safely requires a deliberately trusted integration rather than a blanket bypass of URL validation.

Apply it

Inspect the checks before and after a redirect. Explain why allowing example.com does not authorize a redirect to a loopback address.

QUESTION 026CONCEPT + REFERENCE CASE#

26. How should HTTP rate limits, redirects, and partial crawls affect indexing?

Read / reveal answer

Rate limits and timeouts indicate unavailable or incomplete source access, not document deletion. Redirects may change origin and therefore change what credentials may safely be forwarded. Crawl limits bound work but can also prevent a complete snapshot.

Mechanism & explanation

The connector tracks statuses such as rate-limited or incomplete traversal, checks redirect destinations, and rejects authenticated cross-origin redirects. Sync can use result authority to decide whether removal inference is permissible.

Risks & safeguards

Retrying an incomplete scan without bounds can overload the source; accepting it as complete can remove data. A bounded source request still needs a host scheduling and retry policy for repeated jobs.

Trade-offs

Tight crawl limits improve predictability while reducing corpus coverage. Completeness must reflect the limit rather than presenting the bounded subset as the whole source.

Apply it

Design a crawl that reaches its configured limit exactly. Determine from the connector's terminal state whether it is authoritative, rather than guessing from the number of returned pages.

QUESTION 027CONCEPT + REFERENCE CASE#

27. What identity and consistency issues arise with object storage?

Read / reveal answer

Object keys identify source items, but content can change under the same key. ETags, version identifiers, metadata, and content hashes can describe different aspects of revision identity. An ETag should not automatically be treated as a universal content checksum.

Mechanism & explanation

An object-storage adapter separates listing and reading and returns provenance through a source-document record. Its full-load path must account for continuation tokens and errors before a scan can authorize removal of absent objects.

Risks & safeguards

Listing and fetching can observe different moments. A host needing exact historical verification should retain source versions or snapshots rather than assuming the latest object body matches a previous citation.

Trade-offs

Versioned reads and snapshot retention cost storage and integration work. Reading only current objects is simpler but weakens reproducibility.

Apply it

Change one object between listing and download. Describe which metadata lets you detect or explain the observed revision and which guarantees the source must provide.

QUESTION 028CONCEPT + REFERENCE CASE#

28. Why is text extraction part of the retrieval quality problem?

Read / reveal answer

Search cannot recover information that extraction discarded or scrambled. PDF reading order, tables, headings, repeated headers, and image-only pages can distort the indexed text. Extraction quality therefore sets an upper bound on downstream retrieval quality.

Mechanism & explanation

Extractors are separate adapters and extractor identity participates in ingestion fingerprints. Changing extraction behavior can require reindexing even if the underlying file bytes did not change.

Risks & safeguards

A successful parse may still yield semantically broken text. The reference design does not supply a universal OCR or table-understanding guarantee; inspect output and use host-selected extractors where needed.

Trade-offs

Rich document parsing improves structure at the cost of dependencies, compute, and more failure modes. Plain text extraction is easier to operate but can lose relationships that answers depend on.

Apply it

Extract a two-column page and a table. Compare the text to the source visually, then write a retrieval question that fails if cell relationships are lost.

QUESTION 029CONCEPT + REFERENCE CASE#

29. Which source metadata must survive into evidence?

Read / reveal answer

Preserve stable source and document identity, revision, title or section, location or offsets where available, and the relevant isolation scope. These fields support deletion, attribution, source opening, and debugging. They are not decorative labels added after search.

Mechanism & explanation

The ingestion coordinator merges document and chunk metadata and stamps the actual source name. It also forwards external_id, provenance, location, and extractor information. Evidence types then normalize attribution fields for consumers.

Risks & safeguards

Metadata may contain secrets or untrusted URLs. Sanitizing a displayed URI is not the same as safely fetching it, and arbitrary metadata should not automatically be logged or rendered as HTML.

Trade-offs

Rich metadata adds storage and schema complexity. Omitting it makes early indexing easy but later provenance reconstruction unreliable.

Apply it

Trace the metadata of two documents with different sources through one ingestion run. Verify that every chunk retains the correct source instead of inheriting one global source label.

QUESTION 030CONCEPT + REFERENCE CASE#

30. Why are watchers insufficient without reconciliation?

Read / reveal answer

A watcher provides low-latency change notifications, but notifications can be missed during downtime, buffer overflow, or process failure. A periodic reconciliation compares the source's current authoritative state against indexed state and repairs divergence.

Mechanism & explanation

The directory module includes watcher and periodic reconciler helpers. Sync plans classify additions, changes, removals, metadata-only updates, and unchanged items so a full comparison need not re-embed everything.

Risks & safeguards

Assuming an event stream is complete leaves permanently stale knowledge after a missed event. Deletion events also need an explicit target; absence of an event is not proof that an item still exists.

Trade-offs

Combining watchers with scans spends extra source I/O but improves eventual correctness. Full scans alone are simpler when freshness requirements are modest.

Apply it

Stop the watcher, edit and delete files, then resume it. Describe how a scheduled reconciliation repairs changes that the live event stream never delivered.

Sources, connectors, and extraction: worked example

Standard library: incomplete scans cannot authorize deletion.

from dataclasses import dataclass
@dataclass(frozen=True)
class Scan:
    complete: bool
    ids: frozenset[str]
def removed(previous, scan):
    if not scan.complete:
        raise ValueError("source state is unknown")
    return previous - scan.ids
assert removed({"a", "b"}, Scan(True, frozenset({"b"}))) == {"a"}
